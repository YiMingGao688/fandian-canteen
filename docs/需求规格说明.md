# 饭点需求规格说明

## 1. 项目目标

为校园食堂提供预约点餐和窗口运营流程。系统包含学生微信小程序、食堂 Web 管理后台和独立只读运营大屏。各端通过 REST API 访问同一后端。小程序沿用校园学号账号，支付现阶段为模拟流程，微信授权登录和真实微信支付尚未接入。

## 2. 角色与权限

| 角色 | 查看 | 可执行操作 |
| --- | --- | --- |
| 学生 | 公开窗口、菜单、公告；本人购物车、预约、收藏、反馈 | 注册登录、点餐、支付模拟、取消/改约、评价、反馈 |
| 窗口工作人员 | 数据库绑定窗口的订单、菜单和反馈 | 接单、备餐、取餐核销、维护本窗口菜品、回复反馈 |
| 管理员 | 全校窗口、订单、菜单、反馈和经营指标 | 跨窗口管理后台业务，也可查看运营大屏 |
| 大屏展示账号 | 脱敏后的全校汇总指标 | 只读查看运营大屏，无学生订单或管理写入权限 |

登录使用 JWT。公开注册接口只能创建学生角色；工作人员、管理员和展示账号由演示数据初始化，不允许客户端自行指定角色或窗口。

| 任务书关注项 | 当前实现 | 对照结果 |

## 4. 主要业务规则

1. 每个预约只能包含同一食堂窗口的菜品，最多 20 份。
2. 下单服务端按数据库价格计算总额；事务锁定用户和预约时段后，原子扣减库存与时段名额。
3. 预约必须在今天或明天且距离取餐开始时间超过 5 分钟；待支付预约 15 分钟超时自动取消。
4. 学生仅能操作自己的预约。预约开始备餐后不允许学生取消或改约；预约取消时仅在首次状态迁移时归还库存和名额。
5. 窗口工作人员仅能处理绑定窗口的数据；管理员拥有全校权限。大屏展示账号只能读取脱敏汇总。
6. 模拟支付成功后生成八位演示取餐码；仅“待取餐”订单可以核销，重复核销被拒绝。
7. 评价只能提交一次，且订单必须完成取餐。意见反馈由学生提交到指定窗口。

## 5. 非功能和运行约束

- API 以 Spring Boot + MyBatis 实现，沿用项目统一 `Result` 返回和业务异常处理。
- 校园认证使用 JWT + Shiro Realm，并关闭 Shiro Session；请求结束清理线程身份。
- 数据库和 Redis 使用本地专用端口，默认只绑定 `127.0.0.1`，不读取上游示例云服务器凭据。
- 当前样例数据、菜品照片和营养估值为演示内容，不能作为真实销售或膳食建议。
