# Graphite Operations 样板验收

## 结果与范围

经营总览已接入现有 Vue 页面，入口 `http://127.0.0.1:15173/#/admin`。总览、订单、菜品库存和学生反馈已统一深色主题，菜单显示图标与中文名称；各页主体正文15px、操作14px、辅助信息至少12px。

设计系统见 `design-system.md`；浏览器可读入口为本目录 `index.html`。

## 五个维度的复核

| 维度 | 发现与落实 |
|---|---|
| 视觉层次 | 主金额采用56px编辑式排版，预约队列集中展示三阶段；今日预约与核销客单价退至次级。减少重复KPI卡壳，缩小排行和表头的垂直占用，让近期预约更早进入视野。 |
| 品牌辨识度 | 复用禾序叶片标识；石墨背景、翡翠绿主线和克制状态色形成一致识别。没有增加霓虹、装饰光框或大面积渐变；玻璃效果集中于工具栏和遮罩。 |
| 信息密度 | 主区宽幅趋势与侧面销量排行、下方预约表和品类偏好形成非对称Bento。品类按份数显示，收入与客单价按核销口径显示，取餐时段标明最近100笔已载入订单范围。 |
| 操作效率 | 队列点击筛选、姓名/订单号/菜品搜索、键盘快捷键、详情抽屉、导出、刷新和专注视图可用。业务写入通过跳转原有模块完成，底部工具栏有独立布局区域。 |
| 实现质量 | Vue组件与ECharts生命周期清理完整；样式按总览状态限定。修复了表格隐藏标题绝对定位导致的小屏溢出。空态、长金额、登录、刷新、退出、模块切换与焦点恢复通过检查。 |

## 验证证据

- `npm.cmd run build` 成功。仍有 ECharts / Three.js 公共包超过500kB的构建提示，本轮未扩展到无关打包调整。
- `scripts/verify_premium_overview.mjs` 完成22项检查，结果见 `verification.json`，没有浏览器脚本异常或样本业务写请求。
- 1440px桌面、1024px、390px检查通过；宽表格在自身容器滚动。完整桌面截图另用1440×1280视口展示全部内容。
- 未登录仍进入管理员登录页；真实管理体验账号登录后读取原有接口，刷新和退出维持原会话流程。
- 原有192个源码文件基线中，只有 `web/src/pages/Workbench.vue` 有变化；其变化为组件接入、视图导航和主题生命周期。
- 后端全部文件、`App.vue / state.js / main.js` 校验一致；`load / syncOrders / advance / pickup / toggle / saveDish / sendReply` 七个已有业务方法内容一致。

未执行会创建、支付或核销订单的旧全链路脚本；本轮通过真实只读页面与浏览器内GET响应样本验证视觉和交互。

## 当前限制与后续

用户管理、系统设置和独立异常订单没有发现对应现有接口，没有添加无效菜单或虚假数据。经营分析先体现为总览内的收入、时段、销量与品类。确认此视觉方向后，再定义并逐页统一其他业务模块；当前切换到订单、库存与反馈均沿用统一深色外壳，原业务写入规则保持不变。
