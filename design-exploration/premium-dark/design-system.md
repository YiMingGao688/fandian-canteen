# 禾序 / Graphite Operations 设计系统

管理端已统一到经营总览、预约订单、菜品与库存、学生反馈四个模块；编辑与回复弹层同样使用深色规范。保留现有 Vue 3 / JavaScript / ECharts 6 技术栈；不迁移 TypeScript、不引入 UI 框架，不修改后端、数据库、接口、支付或权限。

## 页面层级与导航

顶部保留品牌、大屏入口、账号与退出；左侧使用164px紧凑导航，直接显示图标与中文名称，仍只导航现有四个模块。经营首页按「核销经营表现 → 当前订单队列 → 趋势与菜品 → 近期预约与品类」组织。主金额用编辑式排版，不做四张等重 KPI 卡。浮动工具栏有独立底部空间，负责查找、处理预约、导出、刷新和专注视图。

## 字体与空间

界面使用系统无衬线（Segoe UI / 苹方 / 微软雅黑）；数字启用 tabular-nums、lining-nums。主金额56px/500，页面标题30px/550，区块标题18px/550，正文和表格15px，导航和操作14px，次级信息至少12px。英文小标题仅作为章节索引，不替代中文字段。采用4px基础间距，卡内20–24px、区块20px、主区28–32px；12列网格，1440px下主图宽于侧栏列表。图表圆角14px、表格10px、详情18px，数值区不强加重复卡壳。

## 图表和数据口径

- 累计核销收入来自 `summary.revenue`；平均核销客单价=收入/已完成订单，分母为0时显示「—」。
- 近七日核销趋势来自已有 `trend`，按已核销订单的下单日期归集；不虚构同比、预测或14日数据。
- 取餐时段图只根据当前已载入订单的取餐日期和时间聚合，排除未支付和取消，明确标注最近100笔数据范围。
- 热门菜品按接口核销份数排序，可关联当前菜品列表打开库存信息；没有精确名称匹配时只展示排行。
- 品类图展示核销份数，不改称营收结构。暂无数据时提供解释和业务入口，不显示虚假的上升趋势。

ECharts 独立定制深色坐标、细线面积、紧凑条形与HTML数值提示；保留可读刻度、键盘可达的表格与说明。不复制默认配置，不用光晕。

## 组件与交互

订单表支持当前状态筛选、学生/单号/菜品搜索、详情抽屉和跳转现有订单处理。业务写入仍在已有模块执行。刷新沿用现有四个读取接口；导出只下载当前已加载指标和趋势。抽屉使用原生dialog管理焦点、Escape和遮罩关闭；搜索支持 `/`，快捷键不抢占输入。加载有禁用反馈，空态提供相关入口。

Hover与选择变化120ms，抽屉/提示160–180ms；支持 prefers-reduced-motion，禁止循环装饰动画。390px改单列，表格区域内滚动；工具栏保留可访问名称。专注模式只隐藏顶部与导航，不改变数据。

参考 [Geist色彩](https://vercel.com/geist/colors) 的表面、边界、状态层级和 [字体](https://vercel.com/geist/typography) 的标题/正文/数字分工；[Linear公开产品页面](https://linear.app/) 用于观察低噪声工作区。以上是原则参考，不是其内部设计Token或完整产品流程。

用户管理、独立系统设置尚无匹配现有接口，此轮不生成空入口；经营分析先作为总览中的真实图表能力。选定方向后再定义后续页面范围。
