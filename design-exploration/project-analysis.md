# 禾序食堂管理：现状与设计判断

检查日期：2026-11-05。本阶段仅阅读现有代码、打开当前页面和制作独立原型。

## 产品与角色

现有项目是校园预约取餐系统，学生端与管理端分离，并有单独的运营数据大屏。此次只探索 Web 管理端首页，不改学生端、小程序、登录页和大屏。

管理端使用 Vue 3、Vite、ECharts 与 Three.js；后端是现有 Spring Boot / MyBatis 体系。页面入口、数据与权限不需要因视觉设计重新建设。

| 用户 | 范围 | 主要工作 | 首页优先信息 |
|---|---|---|---|
| ADMIN | 全校食堂 | 看经营、协调窗口、关注预约和反馈 | 核销收入、队列、窗口对比、趋势 |
| STAFF | 绑定窗口 | 接单、备餐、核对取餐、维护菜品库存、回复反馈 | 待接单、备餐、待取餐、库存提醒 |

- `web/src/pages/Workbench.vue`：管理壳、四个业务模块、账号角色判断、管理范围、数据刷新。
- `web/src/components/OverviewDashboard.vue`：经营收入、订单队列、近七日趋势、热门菜品、分类偏好与近期订单。
- `web/src/workbench-ui.css`、`web/src/admin-layout.css`：后台排版与页面外壳样式。
- `web/src/App.vue`、`web/src/state.js`：主页面与状态、接口调用。
- `backend/sky-server/src/main/java/com/sky/campus/CampusCatalogService.java` 的 `dashboard()`：由 Mapper 聚合收入与图表数据，按窗口权限筛选；无交易日补零。
- `research/current-admin.png`：实际打开现有管理端后的截图，用于现状判断；其中空数据只反映当时体验账号，不代表产品所有环境。

当前导航包括经营概览、预约订单、菜品与库存、学生反馈。顶部保留账号与大屏入口。当前页面已经有 Bento 主次与深绿色队列，不应把它描述成完全未经设计的默认模板。

## 业务口径与信息密度

`summary` 包含 `revenue / totalOrders / todayOrders / completed / pending / preparing / ready`。收入统计已完成取餐订单；今日预约、累计核销与当前待办不是同一时间范围。订单状态 2、3、4、5 对应待接单、备餐中、待取餐、已完成。

管理页约每 5 秒同步订单，约每 20 秒刷新其他看板内容；原型不模拟为真实推送，也不据此声称性能提升。现有后端权限必须在将来正式实施中沿用。

首页适合中等信息密度：四个主要经营指标、一张主要趋势、一个工作清单和一个菜品或窗口上下文。订单模块适合更高密度，但无需把所有字段都挤进首页。

## 当前 UI 的具体问题

1. **决策与操作权重接近。** 收入主卡与队列比较醒目，但趋势、偏好和近期订单并排后，接单、库存和反馈的下一步还不够直接。
2. **空状态占据大量画布。** 当体验账号暂无经营数据时，趋势保留坐标、分类区域留空；应说明口径并给业务入口，避免让空图成为视觉中心。
3. **辅助字体偏小、灰度偏轻。** 表头、说明和图例比主指标弱很多，长时间工作时可读性需要改善。
4. **布局节奏仍偏相似。** 多个模块使用相近圆角、面板和边界；可以探索无框列表、时间轨道、窗口比较或编辑式账页，不必所有信息都进入矩形卡片。
5. **导航辅助内容相对冗余。** 仅四个业务模块，工作区说明和介绍信息应更克制，把空间留给操作。
6. **角色差异没有成为首页重心。** 全校管理员需要横向比较，窗口人员需要尽快处理；十套方案展示这两种工作模式的不同权重，不假定所有角色都需要相同首页。

## 本轮设计边界

- 不修改路由、登录、账号、权限、接口、数据库、Redis、支付和原有业务源码。
- 原型的学生名、订单、收入和容量均是人工构造的 Mock；不读取个人信息。
- 07 / 08 的容量矩阵和 09 的规则任务入口是设计探索，正式落地前需要核对接口适配；09 不宣称已有 AI 服务。
- 原型使用本地 SVG / CSS 图表，便于离线打开、比较设计；选定后在现有 ECharts 技术栈上定制，不迁移图表框架。
- 已保存业务源码 SHA256 基线，完成后重新比较，结果在 `qa/verification.json`。

## 设计选择建议

日常综合经营优先 01；品牌质感可比较 03 和 10；高峰操作比较 02、07、08；偏极简的长时间办公比较 04；05、06、09 用来判断是否接受不同的导航或工作模式。

十套详细差异见 `comparison.md` 和画廊。当前只等方案选择，未进入正式开发。
